# What Are We Assuming

Run a [Key Assumptions Check](https://www.cia.gov/resources/csi/static/955180a45afe3f5013772c313b16face/Tradecraft-Primer-apr09.pdf) (CIA *Tradecraft Primer*, printed pages 7-9):

> The goal is not to undermine or abandon key assumptions; rather, it is to make them explicit and identify what information or developments would demand rethinking them.

> A four-step process will help analysts:
>
> 1. Review what the current analytic line on this issue appears to be; write it down for all to see.
> 2. Articulate all the premises, both stated and unstated in finished intelligence, which are accepted as true for this analytic line to be valid.
> 3. Challenge each assumption, asking why it “must” be true and whether it remains valid under all conditions.
> 4. Refine the list of key assumptions to contain only those that “must be true” to sustain your analytic line; consider under what conditions or in the face of what information these assumptions might not hold.

Check for the [XY problem](https://xyproblem.info): ask what goal a requested fix serves before building it, then treat confirmed preferences as hard constraints.

Verify what you can yourself; ask the user only when the answer changes your action, otherwise state the assumption and proceed. When an assumption breaks, update only what depended on it. Check assumptions hidden inside your tools and methods too: observability, rollback, stationarity ([Marcus Hutter on reinforcement learning's hidden assumptions, Lex Fridman Podcast #75](https://lexfridman.com/marcus-hutter/)). Before calling behavior erratic, ask what premises make it rational ([Anca Dragan, Lex Fridman Podcast #81](https://lexfridman.com/anca-dragan/)).
