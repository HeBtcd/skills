# Functional programming

The discipline, in the order a modeling or refactoring task meets it:

1. **Make illegal states unrepresentable.** Stacked optional fields or booleans (coined: flag-stacking) leave illegal combinations constructible. Define the data variants *before* the function — sum and product types, one branch per variant, structural recursion where the data is self-referential, total functions, exhaustive matching — and parse into precise types once at the boundary. Keep a wish list of pure helpers (name, signature, one-line purpose). The [HtDP recipe](https://htdp.org/2023-8-14/Book/part_one.html): "a good programmer designs programs; a bad programmer tinkers until the program seems to work." (Coined by Minsky; [Wlaschin](https://fsharpforfunandprofit.com/posts/designing-with-types-making-illegal-states-unrepresentable/); [Haskell 2010 Report §4.2.1](https://www.haskell.org/onlinereport/haskell2010/haskellch4.html))
2. **Non-trivial domain → model it in Haskell first.** ADTs for variants, total functions for rules, exhaustive matching for coverage — get it compiling before writing production code ([Brady, Type-Driven Development](https://www.manning.com/books/type-driven-development-with-idris)). The compiled model is the executable spec; port it preserving its types, so a divergence between model and code is a bug, not a style choice.
3. **Functional core, imperative shell.** Branching and domain rules live in a pure value-in/value-out core glued with higher-order combinators (`map`/`filter`/`fold`/`flatMap`); I/O, mutation, time and randomness live in a thin outer shell ([Bernhardt](https://www.destroyallsoftware.com/screencasts/catalog/functional-core-imperative-shell)). Unobservable local mutation preserves referential transparency; reach for free monads or effect ASTs only when you need multiple interpreters. Keep operations orthogonal with no hidden cross-state coupling ([Raymond, TAOP ch.4](http://www.catb.org/esr/writings/taoup/html/ch04s02.html)); hide change-prone decisions behind narrow module boundaries ([Parnas, CACM 1972](https://doi.org/10.1145/361598.361623)).
4. **Every rewrite preserves semantics** — across all valid inputs, evaluation order, cancellation and lifetimes; semantic transparency is what makes a transform legal rather than a rewrite that happens to pass ([Leroy, CompCert, CACM 2009 §1](https://xavierleroy.org/publi/compcert-CACM.pdf)). When the rewrite is a compiler/IR lowering — constructs `C` into primitives `P` under combinators `K` — every `c ∈ C` needs a finite lowering into the subuniverse generated by `P` ([Burris, Universal Algebra §II.3](https://www.math.uwaterloo.ca/~snburris/htdocs/UALG/univ-algebra2012.pdf)); drop a primitive only when the remaining primitives express it or the primitive set's owner signs off.

## Gotchas — observed failures

- Extract typeclasses or higher-kinded abstractions only after several concrete types share the shape.
- In hot loops, keep functional structure without per-iteration closure or combinator allocations.
- Keep fault recovery in an external supervisor rather than inside pure domain types.
